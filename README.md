# Chicken's Kingdom · web, Pollit-IA y backoffice

Website, AI ordering assistant (**Pollit-IA**), order database, public order tracking (**Sigue tu pedido**) and staff backoffice (`/admin`) for **Chicken's Kingdom Bolivia**: fried chicken and pipocas since 2000, 14 branches in Cochabamba and Santa Cruz.

All facts, prices, photos and videos come from the brand's own channels: [Instagram](https://www.instagram.com/chickens.kingdom.bolivia/) and the official menu and branch cards on [chickenskingdom.com](https://www.chickenskingdom.com/). Each fact has a source comment in `js/data.js`.

## Stack

- Static site with no build step (HTML, CSS and vanilla JS), deployed on Vercel.
- One Vercel function for the assistant: `api/pollitia.js` (Claude or NVIDIA NIM).
- Supabase (Postgres + Auth + Realtime) for orders, customers, branches, staff and audit.
- Backoffice: native ES modules plus Supabase JS v2 from a CDN, with no bundler.

```
index.html            homepage + SEO          css/styles.css   design system (sampled brand tokens)
js/data.js            ALL content + catalog() → shared by the site, the assistant AND the DB seed
js/config.js          public backend config (Supabase URL + publishable key, siteUrl, tracking path)
js/app.js             carousel, cart, WhatsApp funnel, live open/closed, assistant UI + voice
api/pollitia.js       assistant: tool-calling agent loop, streams NDJSON events
api/_tools.js         deterministic tools (menu, cart, deals, order, handoff) + JSON schemas
api/_prompt.js        system prompt (cached) + live context      api/_persona.js   one-liners
api/_backend.js       calls place_order / track_order with the publishable key (6 s timeout)
sigue-tu-pedido/      public order-tracking page
admin/                backoffice (index.html, admin.css, lib.js, app.js, views/*.js)
supabase/migrations/  001_core_schema.sql, 002_ops_security_rpcs.sql, 003_rpcs.sql
supabase/seed.sql     generated by scripts/seed-sql.js (never edit by hand)
tests/                tools.test.js (npm test), backend.e2e.js (live), db/ (local Postgres checks)
```

## Features

- **Homepage**: promo ticker, header with pill menu, a five-banner promo carousel (Combo Queen, Wednesday Combo Yape, Pipocas, Combo King, Medio Pollo), the "¿Dónde quieres tu pedido?" box, a promo-card row, weekly promos (today is highlighted automatically, America/La_Paz time), menu with tabs, combos, Instagram reels, the 4-step WhatsApp funnel, 14 branches with live open/closed status, ice creams, story, feed and footer.
- **Cart**: persisted in `localStorage`, and the same cart the assistant edits live.
- **Mi Pedido**: the last 3 orders on the device ("lo de siempre", 🍗).
- **Entrega con Pin**: the customer shares their location, which becomes a maps link in the order.
- **Sigue tu pedido**: `/sigue-tu-pedido/?t=<token>` shows the live status, polling every 15 s.

## Pollit-IA (assistant)

The model only *proposes* tool calls. `api/_tools.js` computes every price, total, deal, opening hour and order from `js/data.js`, and the database prices every order again from its own `menu_items` table.

- **Request**: `POST /api/pollitia { messages, state, channel: "text"|"voice" }`.
- **Response**: an NDJSON stream of events: `text`, `cart`, `options`, `readback`, `location`, `order`, `track`, `handoff`, `state`, `error`.
- **Server-enforced confirmation**: an order is only placed when the customer's newest message is a clear "sí" to the read-back shown in the previous turn. The server places it *before* the model runs. A repeated "sí" never duplicates an order.
- **Models**: `claude-sonnet-5-5` for text and `claude-haiku-5-5` for voice. The static system prompt is cached (`cache_control`); the live context goes in a second, uncached block.
- **Voice mode**: Web Speech API (push-to-talk or hands-free, barge-in, wake lock). It reads "Bs 56" aloud as "56 bolivianos".
- **Without a key**, the chat shows a friendly "coming soon" message, with no errors.

| Variable | Purpose |
|---|---|
| `ANTHROPIC_API_KEY` | Claude key (`ai_provider: anthropic`) |
| `POLLITIA_MODEL` / `POLLITIA_VOICE_MODEL` | optional overrides (defaults `claude-sonnet-5-5` / `claude-haiku-5-5`) |
| `NVIDIA_API_KEY` | NVIDIA NIM key (`ai_provider: nvidia`) |
| `POLLITIA_NVIDIA_MODEL` | optional NIM model (must support tool calling) |
| `POLLITIA_PROVIDER` | optional, forces `anthropic` or `nvidia` |

**Teaching it new words.** Searches it couldn't answer are logged in the Vercel function logs as `{"evt":"pollitia_miss", ...}`. Add the word to `SYNONYMS` in `api/_tools.js` and add a case to `tests/tools.test.js`.

## Backend (Supabase)

### Setup (one time)

1. Create a Supabase project in the region closest to Bolivia (São Paulo, `sa-east-1`).
2. In the SQL Editor, run `supabase/migrations/001…`, `002…` and `003…` in order. Then run `node scripts/seed-sql.js > supabase/seed.sql` and run that file too.
3. Create the **owner**: Authentication → Users → *Add user* (email and password). Then run in SQL:
   ```sql
   insert into public.staff (user_id, full_name, email, role)
   select id, 'Nombre del dueño', email, 'owner' from auth.users where email = 'dueno@ejemplo.com';
   ```
   Create everyone else from `/admin` → Equipo.
4. Fill in `js/config.js` with `supabaseUrl` and the **publishable** key (Project Settings → API Keys) and redeploy. The publishable key is designed to be public, because row-level security limits what it can do. The service-role key is never used.
5. Dashboard settings: Authentication → turn **off** "Allow new users to sign up" and turn **on** leaked-password protection. Then run the Security and Performance Advisors and fix any warnings.

### Schema, security and roles

- Tables: `stores`, `menu_items`, `store_item_availability` (sold out per branch), `staff`, `customers`, `customer_addresses`, `orders`, `order_items`, `order_events`, `audit_log`, `store_daily_counters`, `cancel_reasons`.
- Order statuses: new → confirmed → preparing → **frying** (*en la freidora*) → ready → out_for_delivery → delivered (plus cancelled).
- **RLS on every table.** Anyone (`anon`) can only read the catalogue and call `place_order` / `track_order`. Staff see only their own branch (owner/admin see all). Status and prices change only through RPCs.
- Roles:
  - **Dueño (owner) / Administrador (admin)**: everything.
  - **Gerente (manager)**: their own branch. Can pause it, reopen orders, move them back a stage, and cancel after preparation has started.
  - **Caja (cashier)**: manual orders and customers.
  - **Cocina (kitchen)**: only confirm → preparing → frying → ready, plus marking items as sold out.
  - **Repartidor (rider)**: only "en camino" and "entregado".
- **Audit log**: an append-only record of changes to prices, statuses, branches, staff and sold-out items.
- **Tracking** returns only the customer's first name: no phone and no address.

### Backoffice `/admin`

Sections: Hoy · Pedidos (live board with a beep) · Nuevo pedido · Clientes (segments + CSV) · Sucursales (pause with auto-resume) · Agotados · Menú · Reportes · Equipo · Auditoría · Mi cuenta.

### Checks

- `npm test`: 26 golden tests for the tools.
- `npm run test:db`: applies the migrations to a **local** Postgres and runs 47 behavioural checks (pricing, idempotency, RLS, roles, audit, reports).
- `node tests/backend.e2e.js ownerEmail ownerPw managerEmail managerPw kitchenEmail kitchenPw`: live checks against the real project. It creates a test order and cancels it.

### Keep prices in sync

The website shows the prices in `js/data.js`; the database charges `menu_items`. After a price change, update **both**: edit in `/admin` → Menú and in `data.js`, or edit `data.js`, regenerate `seed.sql` and run it again.

## WhatsApp funnel and routing

Step 4 first records the order (`place_order`, idempotent per cart). It then opens WhatsApp with the code and the tracking link. If the database is unreachable, WhatsApp still opens without a code, so an order is never lost.

Only the official WhatsApp (+591 70343229) is published, so every branch uses it today. To route orders to a branch's own WhatsApp, fill in `branches[].whatsapp` in `js/data.js` and the WhatsApp field in `/admin` → Sucursales.

## Run locally

```bash
npm install
npm test
npx vercel dev
```

Use `?dia=3` (0 = Sunday … 6 = Saturday) to preview another weekday's promo highlighting.

## Updating content

Everything lives in `js/data.js`: menu, promos (with `until` dates), combos, branches, reels and feed. The carousel banners are written in `index.html`, so keep their prices in sync. The **Combo Yape** (Wednesdays, Bs 20) ends on **30/12/2026**; after that the site and the assistant hide it automatically.
